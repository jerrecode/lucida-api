# ADR-0001: Single reusable Python backend, two thin frontends

Date: 2026-11-02. Status: Accepted for experimental 0.1.0 vertical slice.

Decision: central `lucida_api` Python package on Python >=3.11, typed dataclasses, async `httpx`, SQLite in application storage, optional loopback FastAPI service. Separate minimal stdlib argparse CLI and optional Qt6/PySide6 GUI. Frontend dependency version range `lucida-api-core>=0.1,<0.2`.

Rationale: portable cross-OS primitives, few runtime dependencies in core, testable API without display stack, no duplicated provider logic. Build direct-media, metadata-only MusicBrainz, and offline fixture providers before external Lucida adapters, since the live website is unverified and third-party web automation is brittle. CLI stays headless; GUI uses a worker QThread for network work.

Consequences and debt: no native Windows verification yet; incomplete public capabilities; Python and Qt packaging overhead; isolated service mode must not be exposed externally. SQL journal isn't a cross-process queue. Host allowlisting + preflight DNS check assumes trusted hosts and does not eliminate DNS rebinding or all TOCTOU races. Hard-link publication may be unavailable on some volumes and must fail safely. This is a preview, not full upstream parity.
